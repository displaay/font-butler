# Font Buttler re-audit — 10 confirmed findings

Audited commit: `4746796` (2026-09-10). Focus: stability, performance, and differences between feature paths. This document records the initial findings and the fixes applied in the follow-up implementation pass.

The most urgent fixes were the bake transaction, enforcement of project pins on transformed output, and synchronous bulk-import work. All ten confirmed findings below are now addressed and covered by the opt-in regression harness.

Priority: **P1** = address next; **P2** = address in the normal fix cycle. Every finding below has an executed reproduction or measurement. Related failures in source comparison and preview resolution are grouped together.

## 1. P1 — Baking can overwrite a version pinned by an active project

**Trigger:** Install a font with a bakeable feature, pin its current fingerprint in a project, activate that project, then bake the feature using the reinstall option.

**Observed:** The bake succeeds and replaces the pinned installed bytes. The project changes from `active` to `inactive` because its required fingerprint is no longer installed.

**Cause:** [bakeFeatures](/Users/daniel/git/font-butler/core/service-lifecycle.ts:562) checks `assertPinnedInstall` against the original source before transformation. [assertPinnedInstall](/Users/daniel/git/font-butler/core/service.ts:3022) permits the operation when that original source matches the pin. The transformed file is subsequently passed as `sourcePathOverride` without validating its fingerprint against the active pin.

**Fix direction:** Validate the exact staged bytes against all active project pins immediately before replacing an existing entry. A newly named, separate copy can follow a separate policy because it does not replace the pinned asset.

**Regression check:** Baking in place must leave an active project's installed fingerprint unchanged or reject the operation before mutation; baking a separate copy should preserve the original project.

## 2. P1 — A failed bake can change the installed font without recording the action

**Trigger:** Bake into the existing font while writing back to its tracked source fails, for example because the source is read-only or its storage becomes unavailable.

**Observed:** Injecting a source-copy failure caused the action to reject, but the installed file already contained the baked bytes. The source still contained the original bytes, and no bake Activity record was added.

**Cause:** [the install commits before the source write](/Users/daniel/git/font-butler/core/service-lifecycle.ts:600). The source overwrite and following metadata save are outside that install's mutation journal. [The service records Activity only after bakeFeatures returns](/Users/daniel/git/font-butler/core/service.ts:898).

**Fix direction:** Treat replacement of the installed copy, source writeback, catalog changes, and completion recording as a coordinated operation. Stage the source write, retain both originals, and roll back both destinations on failure. Preserve a recoverable journal across a process exit.

**Regression check:** Inject failures at source write, source rename, and catalog save; verify bytes, metadata, and Activity remain consistent. The regression harness also injects this later failure point.

## 3. P1 — Bulk imports block the main event loop and repeatedly rewrite the entire catalog

**Trigger:** Import a folder containing hundreds or thousands of distinct files.

**Observed:** An isolated benchmark using tiny, valid synthetic fonts measured:

| Imported files | Import duration | Timer delay on the same event loop | Catalog bytes written | Final catalog size |
| --- | ---: | ---: | ---: | ---: |
| 100 | 409 ms | 409 ms | 4,833,951 | 95,697 |
| 500 | 3,864 ms | 3,888 ms | 119,924,957 | 478,802 |
| 1,000 | 8,997 ms | 9,057 ms | 479,277,754 | 957,672 |

The final catalog was under 1 MB, but producing it wrote about 479 MB. These are one-run baseline measurements on this machine, not native installation or whole-UI frame-rate measurements. After batching persistence and yielding between import chunks, the same harness measured 86 ms / 63 ms timer delay / 95,689 bytes for 100 files, 369 ms / 31 ms / 478,798 bytes for 500 files, and 670 ms / 27 ms / 957,641 bytes for 1,000 files.

**Cause:** [importPaths](/Users/daniel/git/font-butler/core/service.ts:549) loops synchronously through every file. Each [importOneUnlocked](/Users/daniel/git/font-butler/core/service-import.ts:117) reloads and saves the growing catalog, and [saveCatalog](/Users/daniel/git/font-butler/core/catalog.ts:91) reads the old file again before serializing and writing the whole replacement. This produces quadratic catalog I/O. The packaged app [imports the server directly into the Electron main process](/Users/daniel/git/font-butler/electron/main.mjs:928), so the same synchronous work also blocks main-process event handling.

**Fix direction:** Maintain one indexed catalog snapshot during a batch, commit it once, and yield between bounded import chunks so the main process remains responsive. Keep durability guarantees when changing the commit strategy.

**Regression check:** Measure event-loop responsiveness and total bytes written at increasing library sizes. Verify partial failures and crash recovery remain correct after batching persistence.

## 4. P2 — Partial batch installation failures disappear from the result and Activity

**Trigger:** Install two fonts together when one remains valid and the other's source disappears before installation.

**Observed:** The service returns the one successful entry. Activity records `succeeded` with one successful item and no record identifying the failed font. The caller cannot distinguish complete success from partial success using the returned payload.

**Cause:** [installMany collects errors](/Users/daniel/git/font-butler/core/service.ts:722) but throws only when every attempted installation fails. It records only successful entries and returns only that array. The same pattern appears in `reinstallMany`. The UI's batch feedback logic needs failed-item data that these routes do not return.

**Fix direction:** Return a structured batch result with per-item outcomes, errors, failed IDs, and an operation ID; persist failures as well as successes. Aggregate those results when the UI runs several families in sequence.

**Regression check:** For one success and one failure, both the response and Activity must report a partial outcome, identify the failed font, and support retrying it.

## 5. P2 — Timestamp-preserving updates are detected live but missed while the app is closed

**Trigger:** Replace a source with different valid font bytes while preserving its modification time and size, with no watcher running; then start the service again.

**Observed:** Startup reports `installed` and retains the old source fingerprint. An explicit watcher-style refresh correctly reports `outdated`. A second reproduction showed that calling the reinstall service while the entry still has `installed` status returns success without replacing the old installed bytes.

**Cause:** [startup source refresh](/Users/daniel/git/font-butler/core/service.ts:2955) skips hashing on matching modification time and size; reconciliation uses the same shortcut. The live watcher explicitly forces hashing. Separately, [installEntry's early return](/Users/daniel/git/font-butler/core/service-lifecycle.ts:130) decides that replacement is unnecessary using only modification time and size, even after staging the incoming bytes.

**Fix direction:** Revalidate content after periods when watcher events could have been missed, and base install no-op decisions on staged/installed fingerprints. Startup hashing is performed once per external source so timestamp-preserving changes cannot remain hidden.

**Regression check:** Cover the same source replacement during live watching, across restart, and through an explicit reinstall with unchanged timestamps and sizes.

## 6. P2 — Preview consumers disagree about where retained installed files live

**Trigger A:** Install a font, deactivate it, then open the Tester or Glyphs pane.

**Observed A:** Card font bytes remain readable from `disabledPath`, but metadata and glyph-name calls throw “No font file is available to preview.” Deactivation intentionally retains `installedPath` as the original destination even though the file has moved.

**Trigger B:** Install only to the Adobe testing folder, then remove the separate source file.

**Observed B:** The Adobe installed file still exists, but the font-byte preview method reports no available font.

**Cause:** [previewMeta](/Users/daniel/git/font-butler/core/service.ts:2268) and `previewGlyph` select the first nonempty path rather than the first existing retained copy. [fontBytesForEntry](/Users/daniel/git/font-butler/core/service.ts:1179) checks existence but searches only legacy Mac/source paths, ignoring Adobe installation records. Other preview/bake/comparison consumers also have separate path-selection logic.

**Fix direction:** Share a resolver that distinguishes a requested source from the current retained installation and searches live and parked copies across all managed destinations. Do not silently substitute different bytes for an explicitly selected source or revision.

**Regression check:** Read preview bytes, metadata, and glyph names for active Mac, parked Mac, active Adobe, and parked Adobe copies, with and without an external source.

## 7. P2 — Undoing a relink restores the path but leaves the incoming source's state behind

**Trigger:** Install version 1, relink to a different version 2 source, then Undo the relink.

**Observed:** Undo succeeds and restores the version 1 path, but the entry retains version 2's source fingerprint, `outdated` status, and `relink-review` hold. The library still claims an update needs review although the source once again matches the installed version.

**Cause:** [the relink inverse](/Users/daniel/git/font-butler/core/service.ts:1879) restores only `sourcePath` and basic availability. It does not restore/recompute source metadata, comparison state, or the prior update hold/policy. Unlike normal relinking, this branch also does not synchronize source watchers.

**Fix direction:** Record the previous source state in the operation or recompute it carefully when undoing, restore the prior hold/policy, and refresh watchers before completing Undo.

**Regression check:** After Undo, assert the path, content fingerprint, timestamps, status, update policy/hold, and watcher coverage correspond to the restored source.

## 8. P2 — Live watch imports ignore pause and exclusions that the initial scan respects

**Trigger:** Configure a paused watched folder or an excluded subfolder. Let a new-file event reach the live watch import handler.

**Observed:** The initial scan imports zero matching files. Passing the same paused/excluded paths through the actual live-import handler adds both fonts to the catalog. Installation is skipped later, but automatic import has already happened.

**Cause:** [importInboxFiles' initial filter](/Users/daniel/git/font-butler/core/service-import.ts:134) checks only `watching`. Pause/exclusions are evaluated later, after import, while startup discovery [applies both before importing](/Users/daniel/git/font-butler/core/service.ts:3139). This contradicts Settings' statement that pause stops automatic imports and updates.

**Fix direction:** Apply the same eligibility predicate before classification, duplicate notifications, and catalog import for both initial scans and live events. Re-evaluate it when queued work executes.

**Regression check:** Initial and live paths must produce the same result for paused folders, excluded subfolders, excluded filenames, and overlapping watched roots.

## 9. P2 — “Install as…” ignores the configured and explicitly requested Adobe destination

**Trigger:** Set the default destination to Adobe only. Install normally, then install a renamed copy. The reproduction also passes an explicit Adobe destination to the rename operation.

**Observed:** Normal installation creates an Adobe copy. The renamed installation writes into the Mac install directory and creates no Adobe copy.

**Cause:** [installRenamedCopy](/Users/daniel/git/font-butler/core/service-lifecycle.ts:261) accepts only replacement/source options, then [unconditionally uses the Mac destination writer](/Users/daniel/git/font-butler/core/service-lifecycle.ts:295). Destination selection from the ordinary install flow is bypassed. New named baked copies use this helper too.

**Fix direction:** Route transformed copies through the shared destination-selection and installation machinery, carrying explicit destination options and the applicable default/owner-folder policy.

**Regression check:** Normal, renamed, and baked-copy installations should honor Mac-only, Adobe-only, and both-destination choices consistently.

## 10. P2 — Batch reinstall repeats global cache clearing for every font

**Trigger:** Reinstall multiple active fonts with cache clearing enabled.

**Observed:** Two fonts caused three calls to `clearFontCaches`. The loop performs one clear per font and one additional clear afterward, including when unchanged entries take the install no-op path.

**Cause:** [reinstallEntry clears caches](/Users/daniel/git/font-butler/core/service-lifecycle.ts:523) on every invocation; [reinstallMany calls it for every item and clears again](/Users/daniel/git/font-butler/core/service.ts:937). Global font, Office, and Adobe cache work therefore grows with batch size unnecessarily.

**Fix direction:** Give batch orchestration responsibility for cache clearing. Use one deliberate cache lifecycle for the operation and avoid clearing when no bytes will change, while preserving activation correctness.

**Regression check:** Assert cache-call counts for one font, a large batch, all no-ops, and a partially failed batch. Verify native behavior separately.
