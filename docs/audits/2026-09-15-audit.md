# Font Buttler — final audit, 15 September 2026

## Assessment

**Three confirmed defects should block release:** uninstalling a parked font can delete another installed font, a source update can bypass the active-font identity check, and `repair()` can save a stale catalog snapshot after restoring a revision.

This document merges the morning pass (nine findings, isolated probes under `docs/audits/2026-09-15-evidence/`) with a second full-code pass the same day. Combined: **26 actionable issues — 3 P1, 12 P2, 11 P3**.

Reviewed commit `f8e94a8` from a clean application working tree at the start of the day. Application code was not changed during either review. P1 means fix before release; P2 means schedule a normal-priority correction; P3 is hardening or performance.

### 1. P1 — Uninstalling a parked font deletes a different installed font

**Reproduction:** install `a/Regular.ttf` as family A, deactivate A, then install `b/Regular.ttf` as unrelated family B. The second install reuses the now-free `Regular.ttf` destination. Uninstall A.

**Observed:** B's installed file is deleted, while B's catalog record still says `installed`. Before the uninstall, previewing A also returns B's bytes. A's remembered live destination and B's actual destination are identical, but A's own bytes are in its disabled vault.

[removeInstalledCopy](/Users/danielquisek/git/font-butler/core/service-helpers.ts:118) unregisters and deletes `entry.installedPath` without distinguishing a remembered destination from an owned live copy. [The preview resolver](/Users/danielquisek/git/font-butler/core/service.ts:185) likewise prioritizes that path over the parked file.

**Fix:** resolve the actual owned copy before reading or deleting files. A parked entry must use its parked bytes; it must not claim a live path another entry has reused. Cover uninstall, destination removal, preview, revision retention, and conflict checks with this sequence.

Evidence: `parked-preview` and `uninstall-parked-reused-name` in [lifecycle-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/lifecycle-results.jsonl).

### 2. P1 — Reinstall validates the old identity rather than the staged font

**Reproduction:** install separate fonts A and B, replace A's tracked source bytes with B's font, refresh source status, then reinstall A.

**Observed:** reinstall succeeds and leaves two live files whose parsed PostScript names are both `IdentityB-Regular`.

[The sibling check](/Users/danielquisek/git/font-butler/core/service-lifecycle.ts:111) runs against the stored entry before [the staged metadata is applied](/Users/danielquisek/git/font-butler/core/service-lifecycle.ts:120). Source-status refresh updates hashes and timestamps, not face identity. The later format-conflict check does not catch a same-format identity collision. [`occupyingSiblingsForIncoming`](/Users/danielquisek/git/font-butler/core/identity.ts:97) already exists for staged faces.

**Fix:** validate the staged font's actual faces and format against all occupied target destinations before committing. Include source exports that change family or PostScript names, not just version-number changes.

Evidence: `source-identity-change` in [lifecycle-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/lifecycle-results.jsonl).

### 3. P2 — Retail persistence can overwrite an uninstall within the same download batch

**Reproduction:** sync two installed retail fonts to new versions. Allow A's file write to finish while B's download is delayed. Uninstall A, then release B's download.

**Observed:** A changes from `uninstalled` back to `installed`, with `verification: file-present` metadata despite the installed file being absent. Sync returns no error.

[writeOne](/Users/danielquisek/git/font-butler/core/retail-apply.ts:135) releases the catalog lock after writing the file. [Persistence waits for the whole batch](/Users/danielquisek/git/font-butler/core/retail-apply.ts:224). The later [catalog write](/Users/danielquisek/git/font-butler/core/service-retail.ts:628) applies the old destination result without checking for an intervening uninstall. The existing later-batch regression test does not cover this same-batch gap.

**Fix:** commit each file's catalog linkage and manifest state within the same serialized mutation, or revalidate a mutation/version token before applying deferred results.

Evidence: [retail-race-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/retail-race-results.jsonl) and [the controlled two-download probe](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/retail-race.mts).

### 4. P2 — Bulk uninstall loses partial results and Undo

**Reproduction:** uninstall two installed fonts in one request, with native removal of the second font failing.

**Observed:** the first font is removed, the second remains installed, and the request throws. There is no new Activity record and no catalog event from the operation. The successful removal has no corresponding Undo action.

[uninstallMany](/Users/danielquisek/git/font-butler/core/service.ts:891) only commits Activity and emits the catalog after the entire loop succeeds. A throw bypasses both. `activateMany` and `forgetMany` use similar fail-fast orchestration and merit the same correction. `installMany` / `reinstallMany` / `deactivateMany` already capture per-item outcomes.

**Fix:** capture per-item outcomes and always persist completed work and emit the resulting catalog, including on partial failure. Return failed IDs and counts so the UI can explain the result and retry the failed items.

Evidence: `partial-uninstall` in [lifecycle-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/lifecycle-results.jsonl). The failure is injected at the native boundary; the first on-disk removal is real inside the temporary library.

### 5. P2 — A failed Adobe destination is silently reported as success

**Reproduction:** request installation to both Mac and Adobe, with a pre-existing unmanaged same-identity font in Adobe.

**Observed:** only the Mac copy is installed, the API returns success, and Activity records a succeeded installation. The requested Adobe failure has no error or partial result. When no previous Adobe copy exists, it is absent even from the destination metadata.

[The Adobe catch block](/Users/danielquisek/git/font-butler/core/service-lifecycle.ts:250) suppresses the error whenever the Mac target was requested. The renamed-copy path repeats this behavior.

**Fix:** preserve the successful Mac installation but return a partial destination result, record the Adobe failure, and provide a retry path.

Evidence: `partial-destination-install` in [lifecycle-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/lifecycle-results.jsonl).

### 6. P2 — Uninstall leaves parked Adobe files behind

**Reproduction:** install only to Adobe, deactivate the font, then uninstall it.

**Observed:** its `parkedPath` file remains in the disabled vault after `installations` is cleared. The catalog no longer tracks that retained file, and it is outside revision-budget accounting.

[removeAdobeCopy](/Users/danielquisek/git/font-butler/core/service-destinations.ts:138) only removes `existing.path`; it never removes `existing.parkedPath`. [uninstallEntry](/Users/danielquisek/git/font-butler/core/service-lifecycle.ts:406) then clears installation metadata and only explicitly cleans the legacy Mac `disabledPath`.

**Fix:** remove the owned parked Adobe copy before dropping its record. Preserve the record if cleanup fails, and verify both active and parked destinations in uninstall tests.

Evidence: `adobe-parked-uninstall` in [lifecycle-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/lifecycle-results.jsonl).

### 7. P2 — The parse worker is unreferenced while requests are pending

[ensureWorker](/Users/danielquisek/git/font-butler/core/font-analysis.ts:227) calls `next.unref()` immediately on `online`; [posting a job](/Users/danielquisek/git/font-butler/core/font-analysis.ts:337) does not reference it again. An awaited promise alone does not keep a Node process alive.

**Observed:** the normal suite cancels 119 tests with “Promise resolution is still pending but the event loop has already resolved.” This persists outside the sandbox and with filesystem polling. A diagnostic preload that keeps the process alive until test teardown removes all 119 cancellations. No application implementation was changed for that diagnostic.

**Fix:** reference the worker while jobs are pending and unreference it only when its queue is empty. Keep shutdown and error handling balanced. The test preload is evidence, not the proposed production fix.

Evidence: [test-results.txt](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/test-results.txt) and [test-liveness.mjs](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/test-liveness.mjs).

### 8. P2 — Every normal preview request parses the catalog twice

[fontBytesForRevision](/Users/danielquisek/git/font-butler/core/service.ts:2598) loads the whole JSON catalog, then the normal installed-preview branch [calls fontBytesForEntry](/Users/danielquisek/git/font-butler/core/service.ts:2616), which loads it again. Reads and JSON parsing are synchronous on the shared API thread.

For 50 requests to small generated fonts, the median of five warm batches was:

| Catalog entries | Catalog size | 50 preview requests |
| --- | --- | --- |
| 100 | 75 KB | 18 ms |
| 1,000 | 749 KB | 161 ms |
| 5,000 | 3.76 MB | 827 ms |

The source font bytes were the same small fixture at every size, isolating catalog overhead. These are direct backend timings, excluding HTTP and browser rendering. In the app, requests arrive as previews load during browsing and scrolling; the synchronous work competes with settings, events, and actions.

**Fix:** reuse the already-resolved entry immediately, then introduce a catalog snapshot/index with explicit invalidation on commits. Avoid serving each font through repeated full-library JSON parsing.

Evidence: [performance-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/performance-results.jsonl).

### 9. P2 — Cold system scanning blocks other API work

[scanSystemFonts](/Users/danielquisek/git/font-butler/core/system.ts:123) parses every uncached font synchronously. The renderer requests `/api/system` during boot even when the user is opening the ordinary library. The scan prevents the API process from answering preview and action requests until it completes.

**Measured on this Mac:** 722 returned faces, **2,788 ms cold**, **256 ms warm**. Only the real system font trees were read; the scan cache was written into a temporary directory. These measurements do not include Core Text registration or UI rendering.

**Fix:** move cold system parsing onto the analysis worker, yield during discovery, and load system inventory when needed or after the initial library is usable.

Evidence: `system-scan` in [performance-results.jsonl](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/performance-results.jsonl).

### 10. P1 — `repair()` overwrites a restored catalog with a stale snapshot

**Reproduction:** install a font to Mac + Adobe, update the source, reinstall (v1 retained as `previousRevisionId`), delete the Mac file, then `repair([id])`.

**Observed:** disk is restored to v1, but the outer `repair()` loop then mutates the pre-restore catalog object and `saveCatalog`s it. Catalog `installedFingerprint` stays at v2; Adobe disk is v1 while catalog still records v2; `previousRevisionId` reverts to v1.

[`repair()`](/Users/danielquisek/git/font-butler/core/service.ts:2190) loads the catalog once. Per entry it may `await restoreRevision()` (fresh load/save), then the Adobe branch mutates the **stale** entry and [saves the outer catalog](/Users/danielquisek/git/font-butler/core/service.ts:2250). UI reaches this via `copyNeedsRepair` → `repairSelected`.

**Fix:** reload the entry after `restoreRevision`; never save the outer catalog object after an inner commit.

Evidence: [second-pass.mts](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/second-pass.mts) (`repair`).

### 11. P2 — Settings accept unclamped numerics

[`updateSettings`](/Users/danielquisek/git/font-butler/core/service.ts:536) and [`loadSettings`](/Users/danielquisek/git/font-butler/core/settings.ts) accept any number. The UI clamps (64 MB / 7 days) but the API does not. Probe stored `(-5, -1, 0)`; the next `listActivity()` pruned operations 1→0. Negative budget also evicts revisions via `revisionStorage()`.

**Fix:** clamp on read and write.

Evidence: [second-pass.mts](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/second-pass.mts) (`settings`).

### 12. P2 — Uploads are fully buffered before the size check

[`importUploads`](/Users/danielquisek/git/font-butler/core/service.ts) `Promise.all`s `file.arrayBuffer()` then checks `MAX_UPLOAD_BYTES`. Check `file.size` first and bound total batch bytes. The HTTP upload path in `server/index.ts` should reject oversized bodies the same way.

### 13. P2 — Watchers are fully rebuilt after nearly every mutation

[`syncWatchers`](/Users/danielquisek/git/font-butler/core/watch.ts:130) closes and recreates the entire chokidar set after catalog mutations. Diff roots and incrementally `add` / `unwatch`.

### 14. P2 — `applyPlan` is O(n²) catalog IO

[`applyPlan`](/Users/danielquisek/git/font-butler/core/service.ts:1672) reloads the catalog multiple times per item and `emitCatalog()` after every item. Use a single snapshot and one emit at the end (throttled progress is fine).

### 15. P2 — Corrupt catalog cannot be overwritten

[`loadCatalog`](/Users/danielquisek/git/font-butler/core/catalog.ts:83) throws on invalid JSON. [`saveCatalog`](/Users/danielquisek/git/font-butler/core/catalog.ts:99) re-reads/validates the existing file before write, so a corrupt file cannot be replaced. Keep a rotating `catalog.json.bak` written after a successful save, and allow save to replace an unreadable catalog.

### 16. P3 — `loadPlan` path traversal

[`loadPlan`](/Users/danielquisek/git/font-butler/core/planner.ts:363) joins `id` into the plans directory without validating it. Probe `../evil` escaped the plans dir. Validate `^[0-9a-f-]{1,64}$` (or equivalent UUID) and resolve containment.

Evidence: [second-pass.mts](/Users/danielquisek/git/font-butler/docs/audits/2026-09-15-evidence/second-pass.mts) (`planTraversal`).

### 17. P3 — `rememberedDecisions` never evicted

The in-memory Map in [`FontService`](/Users/danielquisek/git/font-butler/core/service.ts:307) grows for every import-plan decision. Cap with LRU/TTL.

### 18. P3 — Activity GET always prunes

[`listActivity`](/Users/danielquisek/git/font-butler/core/service.ts:1866) calls prune + `revisionStorage()` on every GET; prune rewrites even when unchanged. Skip the rewrite when the pruned set equals the loaded set; do not evict revisions on a read.

### 19. P3 — API worker exit-1 is treated as a bound port

[`spawnApiWorker`](/Users/danielquisek/git/font-butler/electron/main.mjs:1059) maps any exit-1 to `EADDRINUSE` and retries 20 ports. Match stderr for the actual bind error instead.

### 20. P3 — Trash is macOS-only

[`moveToTrash`](/Users/danielquisek/git/font-butler/core/reveal.ts:44) always uses osascript/Finder. Gate on `isMac()`; on other platforms use a safe unlink or no-op with a clear error for `forget --deleteFiles`.

### 21. P3 — Retail download without `content-length`

[`core/retail-client.ts`](/Users/danielquisek/git/font-butler/core/retail-client.ts:186) will `arrayBuffer()` an unbounded body if the header is missing. Cap reads to the same max used for uploads/retail files.

### 22. P3 — Credentials-only retail check still downloads the manifest

[`checkRetail({credentialsOnly})`](/Users/danielquisek/git/font-butler/core/service-retail.ts:755) downloads the full manifest then discards it. Short-circuit after credential validation.

### 23. P3 — Static assets re-read from disk

[`server/index.ts`](/Users/danielquisek/git/font-butler/server/index.ts:42) `readFileSync`s per request. Cache in memory for the process lifetime (dev can skip the cache).

### 24. P3 — Redundant catalog refetch after mutations

[`useFontActions`](/Users/danielquisek/git/font-butler/src/hooks/useFontActions.ts:714) refetches catalog+activity after every action despite SSE. Trust the event stream (or refetch only when SSE is disconnected).

### 25. P3 — SSE reconnect has no backoff

[`src/lib/api.ts`](/Users/danielquisek/git/font-butler/src/lib/api.ts:444) and [`electron/main.mjs`](/Users/danielquisek/git/font-butler/electron/main.mjs:871) reconnect on a fixed 2s interval forever. Add exponential backoff with jitter and a cap.

### 26. P3 — Catalog revision is a timestamp sum

[`catalogRevision`](/Users/danielquisek/git/font-butler/core/planner.ts:336) sums `updatedAt`. Prefer a stable hash of `(id, updatedAt)` that still fits the existing numeric field.

The additional normal-suite failure is an environment-dependent test assumption: [destinations.test.ts:85](/Users/danielquisek/git/font-butler/core/destinations.test.ts:85) points at the real `/Library/Application Support/Adobe/Fonts` and asserts it is unavailable. ## Reproduce

Run from the repository root with the existing dependencies and Python fonttools available. The probes use temporary catalogs, mock native operations, and print observed behavior; they do not modify the user's font library. The retail probe uses injected downloads and does not contact a server.

```sh

```
